Understanding ReportBuilder

A single build takes one dated DataFrame and produces one workbook, one JSON tree per section and a web index. This walkthrough follows the Global Markets V1 build for 27 November 2026.

from report_builder import ReportBuilder

index_path = ReportBuilder().build_report(
    "global_markets", "2026-11-27", "V1", dataframe=v1_df
)

Read the report definition for section order, input filters and Excel placement. Read the section YAML for grouping and rollup rules, and the EOM mapping for display columns. The Python excerpts below follow the builder source from top to bottom.

Dependencies

The builder coordinates three kinds of work. Python’s standard library handles JSON, dates, paths and temporary folders. NumPy helps convert numeric results for storage. The two local imports do the report-specific work: generate_report calculates a tree from rows and ExcelReportGenerator draws that tree on a worksheet.

Convert a single JSON value

An aggregation can return a NumPy integer that Python’s JSON encoder cannot write directly. Calling .item() extracts a native Python value. A date becomes an ISO-formatted string. Raising TypeError for other unsupported objects makes a bad value visible during generation.

Python · lines 12–17
def _json_scalar(value):
    if isinstance(value, np.generic):
        return value.item()
    if isinstance(value, date):
        return value.isoformat()
    raise TypeError(f"Unsupported report value: {type(value).__name__}")

Write a section or index to disk

The with block opens the destination as UTF-8 text and closes it even if writing fails. json.dump walks the whole dictionary, calling _json_scalar only when it encounters an unfamiliar type. indent=2 makes the file readable and ensure_ascii=False preserves readable Unicode labels. allow_nan=False rejects NaN and infinity, which standard JSON cannot represent.

Python · lines 20–23
def _write_json(path, data):
    with path.open("w", encoding="utf-8") as stream:
        json.dump(data, stream, default=_json_scalar, ensure_ascii=False,
                  allow_nan=False, indent=2)

Locate the project

Constructing ReportBuilder stores one absolute path in self.root. By default this is the directory containing report_builder.py, so launching Python from another folder still finds the configs. Passing project_root lets a caller point the same builder at another report installation.

Filter the original data for one section

A mask is a True/False choice for each row. isin checks membership, ~ reverses that choice for not_in, and notna implements not_null. rows.loc[mask] keeps the matching rows. Applying the next rule to those survivors gives AND across rules. With no filters the method returns the input frame. A missing column or invalid rule raises an error with the section ID.

For Risk Summary, Asia/HKG and Japan/Tokyo pass. Eur/Internal passes the region rule but fails the desk rule. Amer/New York fails the region rule. Each section starts afresh, so the regional summary can still include all four input rows before its own rollup rules apply.
Python · lines 30–47
    @staticmethod
    def _section_data(dataframe, section):
        rows = dataframe
        for rule in section.get("filters", []):
            column = rule["column"]
            operator = rule["operator"]
            if column not in rows.columns:
                raise ValueError(f"{section['id']}: missing filter column {column!r}")
            if operator == "not_null":
                mask = rows[column].notna()
            elif operator in ("in", "not_in") and isinstance(rule.get("values"), list):
                mask = rows[column].isin(rule["values"])
                if operator == "not_in":
                    mask = ~mask
            else:
                raise ValueError(f"{section['id']}: invalid filter for {column!r}: {rule}")
            rows = rows.loc[mask]
        return rows

Accept a dated build request

The caller supplies the report ID, date, edition and DataFrame. Version validation admits Daily, V1 and V2. A date string is parsed with date.fromisoformat; a datetime loses its time component. The caller is responsible for supplying the snapshot that belongs to that date and edition.

Python · lines 49–56
    def build_report(self, report_id, report_date, version, dataframe):
        """Build one dated report from the supplied DataFrame and return its index path."""
        if version not in ("Daily", "V1", "V2"):
            raise ValueError("version must be Daily, V1, or V2")
        if isinstance(report_date, str):
            report_date = date.fromisoformat(report_date)
        if isinstance(report_date, datetime):
            report_date = report_date.date()

Resolve configuration and mapping paths

The builder opens the report definition, selects the requested entry under versions and adds the report ID and date to context. The **context syntax passes those entries by name when expanding each path template. It then loads the mapping in file order, reads the ordered section list and picks up any shared Excel options.

For V1, config_version is EOM and suffix is _V1. The mapping resolves to config/EOM/global_markets/mapping.json. V2 reads the same config directory while using its own dataset and filename suffix.
Python · lines 57–66
        definition = load_config(self.root / "report_config" / report_id / "report.yaml")
        context = dict(definition["versions"][version], report_id=report_id, date=report_date)
        output = definition["output"]
        directory = self.root / output["directory"].format(**context)
        config_directory = definition["config_directory"].format(**context)
        configs = self.root / config_directory
        mapping_path = self.root / definition["mapping"].format(config_directory=config_directory, **context)
        mapping = json.loads(mapping_path.read_text(encoding="utf-8"))
        sections = definition["sections"]
        defaults = definition.get("excel", {}).get("defaults", {})

Plan filenames before writing

The workbook and web index each get a filename. Each section uses json_filename if provided, otherwise the report’s section_json template. The builder requires at least one section, distinct section IDs and distinct output filenames. casefold catches names that differ only in capitalization. Path(name).name screens out directory components.

The Risk Summary filename resolves to risk_summary_20261127_V1.json. The workbook and index names join the same files list, so a section cannot accidentally take the workbook’s name.
Python · lines 67–76
        workbook_name = output["workbook"].format(**context)
        index_name = output["web_index"].format(**context)
        names = [section.get("json_filename", output["section_json"]).format(
            section_id=section["id"], **context) for section in sections]
        files = [*names, workbook_name, index_name]
        if not sections or len({s["id"] for s in sections}) != len(sections):
            raise ValueError("Configure at least one section and use distinct section IDs")
        if (len({name.casefold() for name in files}) != len(files)
                or any(Path(name).name != name or name in ("", "..") for name in files)):
            raise ValueError("Each output must have a distinct filename within the report directory")

Compute and stage each section

mkdir creates the dated output folder and any missing parents. TemporaryDirectory creates a working folder inside it. zip pairs each section definition with its planned filename. For every pair the builder filters the original DataFrame, sends that subset and the section YAML to the engine, and writes the returned tree to staging.

The same tree goes to both JSON and Excel. The engine can calculate extra metrics in the tree. The mapping determines which metric columns the reader sees and in which order.
Python · lines 83–89
        directory.mkdir(parents=True, exist_ok=True)
        with TemporaryDirectory(dir=directory) as temporary:
            stage = Path(temporary)
            for section, name in zip(sections, names):
                rows = self._section_data(dataframe, section)
                tree = generate_report(rows, configs / section["config"])
                _write_json(stage / name, tree)

Choose the sheet and starting row

The builder makes a fresh options dictionary for this section. setdefault fills a missing setting while preserving an explicit setting. New sheets start at row 3 by default. A later section on Markets takes its start row from next_rows for Markets; the Risk worksheet has its own position.

Python · lines 90–92
                options = defaults | section["excel"]
                sheet = options.setdefault("sheet_name", "Global")

Reserve space for an optional banner

pop removes merged_heading from the options sent to create_report. If present, the heading defaults to the section start row, and an explicit row_number takes precedence. The builder checks that the row is a positive integer and that it falls at or after the sheet’s next available row. max keeps the report body below the banner while respecting a later configured start.

Risk Summary requests C2:H2. With the default body start at row 3, the header stays on row 3. Moving the banner to row 8 would move that header to row 9.
Python · lines 93–101
                heading = options.pop("merged_heading", None)
                if heading:
                    heading = {"row_number": options["start_row"], **heading}
                    row = heading["row_number"]
                    if type(row) is not int or row < 1:
                        raise ValueError(f"{section['id']}: merged_heading.row_number must be a positive integer")
                    if row < next_rows.get(sheet, 1):
                        raise ValueError(f"{section['id']}: heading row {row} precedes the next available row on {sheet}")
                    options["start_row"] = max(options["start_row"], row + 1)

Render the section and register it

create_report receives the tree, the entire mapping and the section’s layout options. It returns the next free row, which the builder remembers for that sheet. Once the generator has selected the correct worksheet, the builder writes any reserved banner. The web index receives the section ID, title, JSON filename and ordered mapping keys.

Finish the build and return its location

After the section loop, the builder embeds the mapping in the index, saves the workbook once and writes the index into staging. _publish installs the planned files. Exiting the temporary-directory block cleans up staging. On success the caller receives a Path to the published index, which identifies the workbook and section files.

            generator.save(stage, workbook_name)

Publish the files for this edition

The lock filename comes from the last planned file, the edition’s index. touch(exist_ok=False) fails immediately if another publisher holds that lock. For each output the builder backs up any existing file and replaces the destination with its staged copy. It records each successful replacement. The index is published last.

V1 and V2 share a dated EOM folder but use separate filenames and index locks. Each file replacement happens separately, so a reader opening files during publication can briefly see different generations.
Python · lines 114–130
    @staticmethod
    def _publish(stage, directory, files):
        # Serialize replacements for this edition and restore prior files on failure.
        from shutil import copy2

        lock = directory / ("." + files[-1] + ".lock")
        lock.touch(exist_ok=False)
        try:
            with TemporaryDirectory(dir=directory) as backup:
                replaced = []
                try:
                    for name in files:
                        target = directory / name
                        if target.exists():
                            copy2(target, Path(backup) / name)
                        (stage / name).replace(target)
                        replaced.append(name)

Recover from a publication error

If copying or replacing a file raises OSError, the builder walks the successfully replaced names in reverse. It restores an old file from backup or removes a newly introduced file, then re-raises the error to the caller. finally normally removes the lock on both success and failure. A hard process termination can interrupt cleanup and leave a lock behind.

Python · lines 131–140
                except OSError:
                    for name in reversed(replaced):
                        previous = Path(backup) / name
                        if previous.exists():
                            previous.replace(directory / name)
                        else:
                            (directory / name).unlink()
                    raise
        finally:
            lock.unlink()
